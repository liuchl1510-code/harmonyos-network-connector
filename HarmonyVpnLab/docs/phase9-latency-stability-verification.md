## 实现

- `Nodes.ets` 对指定节点创建临时 `node-latency` 会话，不调用选择节点接口。列表在检测和清理期间锁定修改。
- UI 单写 `latency-request.json` 与 `latency-proof.json`；服务读取快照并验证 runId、节点 ID、SHA-256 配置指纹和网络代次。新核心与 TUN 只接管本应用。
- HTTPS 必须在 UI 进程发出：VPN 服务进程本身已被系统保护而绕过 VPN。计时是单次完整 HTTPS 小响应耗时，不包含 VPN 建立，不预先做 DNS 预热；不代表 TCP RTT 或速度测试。
- 固定请求 `https://www.cloudflare.com/cdn-cgi/trace`，8 秒单调时限、4096 字节上限、无重定向/缓存、正常 TLS。验证状态码及固定 trace 字段，不保存响应正文和出口 IP。
- 服务只在当前会话仍 active、快照 active 且双向计数有限且大于零时接收 passed。停止命令和新 run 在异步统计读取前后均再验证。网络变化取消测量，不把跨网络完成的结果记到节点上。
- 单节点历史记录以原始 outbound 文本 SHA-256 绑定，最多 500 条；严格字段、大小、状态、原子写入。配置有变则不显示旧耗时。取消或失败明确显示原因，不显示伪造的 0 ms 成功。
- `DiagnosticJournal.ets` 由服务单写，最多 200 条/64 KiB，只有固定事件类别、网络类别、时间和数字计数。Socket 回调只累计过期前/过期后/系统保护失败次数，在心跳/停止时持久化；不会为每个 socket 同步 fsync。

## 持续观测方法

`scripts/measure-device-stability.cjs --pid 5996 --ui-pid 4334 --run-id 1788870501507 --minutes 30 --interval-seconds 30`

样本逐次写入 `build/stability/1788870501507/samples.jsonl`，结束后生成 summary.json与analysis.json。只按已核对的 PID 读取 proc，前后检查进程启动 ticks，拒绝 PID 重用。HDC 单命令 10 秒时限，采集周期以电脑单调时间计算。没有权限的 FD 数记 null 和固定原因，不把不可读当作 0。

CPU 同时保留原始 ticks，并明确暂用 100 Hz 假设。手机的 `getconf CLK_TCK` 不可用，未把该假设写成实测。周期读取过滤后的应用日志只用于固定事件计数，缓冲区快照不保证无丢失。起始/结束实际 HTTPS 是独立验收步骤。

观测期间对内存进行了有界源码检查：控制轮询只有一个 interval；状态/网络/通知任务有并发保护并清引用；普通连接不执行临时延迟任务。日志读取尾部最多1 MiB，记录200条/64 KiB封顶；Go的C返回缓冲由`CGoFree`释放，NAPI异步对象和工作句柄在完成路径释放。未找到明确无限保留点，但对象分配、GC和分配器高水位仍可影响RSS。这不是堆分析，也不能证明没有泄漏。

USB连接可能充电，本次不测续航；单个30分钟窗口不代表全天稳定、满负载吞吐、全部协议或更多机型兼容。FD目录无权限，未完成文件句柄总量/增长验收；清理确认依赖关闭日志、网卡销毁结果、保护活动数归零及服务退出，二者不能混为一谈。用户没有服务器域名或真实订阅URL，因此这两类端到端验收仍待可用条件。IPv6仍为捕获后阻断，未实现IPv6代理或VPN关闭后的kill-switch。
