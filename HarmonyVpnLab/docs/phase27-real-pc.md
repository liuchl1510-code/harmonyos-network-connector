# 0.22.0：真实 HarmonyOS 电脑验证

本轮于 2026-09-22 在真实 `2in1` 设备上测试，系统 API 26、CPU 为 AArch64，应用 ABI 为 `arm64-v8a`。它使用完整 VPN 核心，区别于此前只能验证界面的 x86_64 电脑模拟器。应用仍为 0.22.0/code43，本轮没有修改应用源码或重建上游原生核心。

**本轮短时验收已完成。** 安装、原生运行时、宽窄窗口的控件检查、两次真实连接及断开清理、诊断摘要复制／TXT 操作均取得对应证据。收尾时恢复原窗口位置、大小及进程字号，节点和设置保持不变，VPN 已断开。此次结果不代表全天稳定性或所有电脑型号兼容性验收。

## 非联网原生检查

在两个独立的新 UI 进程中，分别冷启动 `runtimeSmoke=fixtures` 和 `runtimeSmoke=go`。每次使用实时应用标签日志，绑定本次设备时间范围、新 UI PID 和新 runId，再核对开始、结果及明确的最终 verdict；没有将启动命令成功或旧日志作为通过依据。

- `fixtures`：正常样例通过，故障对照样例按预期失败，寄存器错误掩码为 64；两个样例均完成 4 个 worker、32 次调用，回复失败数为 0。
- `go`：4 个 worker、32 次调用全部完成，寄存器错误和回复失败均为 0，最终 verdict 通过。

这些检查不创建 VPN，不接管设备网络。它们证明当前电脑上的受测运行时路径可执行，实际代理联网仍由后面的独立连接测试确认。

## 真实窗口检查

通过本应用的 debug 参数请求窗口大小及进程内字号，不修改显示器分辨率或系统字体设置。结果依据应用可访问性树（AX）的当前控件、焦点和几何记录：

| 条件 | 页面与观察 |
| --- | --- |
| 360 × 900 vp 窄窗 | 首页、节点、设置、连接诊断、诊断摘要；主页面存在“连接／节点／设置”胶囊和独立圆形启停按钮 |
| 1400 × 950 vp 宽窗、2 倍字号 | 首页、设置、诊断摘要；主页面切换为侧栏，摘要返回、刷新、复制及保存入口仍在应用窗口内 |

实际记录的窄窗尺寸为 684 × 1710 px，宽窗为 2660 × 1805 px，与本次显示缩放下请求的逻辑尺寸对应；窗口包含系统标题栏。摘要使用独立滚动区，长文本并非一次全部显示在可见区域内。

本轮实体电脑的桌面还存在其它可见窗口，因此以本应用 AX 结构和几何作为证据，没有把整屏截图作为公开图片。上述结果不等同于液态玻璃材质、像素色差、所有主题及所有系统缩放组合的视觉验收。此前模拟器的图片结果也不替代这台真机的视觉结论。

## 真实连接、返回与重新连接

本轮使用电脑当前 Wi-Fi 网络，经应用正常连接入口进行测试。授权节点经 UI 导入，未将旧手机或模拟器的 service state、command、日志、恢复记录或清理回执注入电脑。

1. 第一次连接进入 `active` 后，应用内检查返回“代理 DNS 与域名 HTTPS 检查通过”。同时观察到真实上传、下载计数和 socket 保护成功计数，检查时保护失败数为 0。
2. 将应用最小化约 6 秒后返回，同一会话仍为 `active`，再次检查 DNS 与域名 HTTPS 通过。此项只说明本次短暂最小化返回成功，不代表睡眠或长时间后台稳定性通过。
3. 通过应用 UI 断开，读取该会话、该服务 PID 的 `phase=destroyed` 与 `cleanupConfirmed=true`。独立再次读取结果稳定，两次 `/proc/PID` 检查和 `kill -0` 均确认原服务进程不存在。
4. 再次连接生成新的 runId 和新的服务 PID，DNS 与域名 HTTPS 检查再次通过，上传和下载计数为正，保护失败数为 0。第二次通过 UI 断开后，也取得同会话清理回执与两次进程不存在的证据。

清理结论同时依赖本次会话身份、服务回执和独立进程检查；没有仅凭页面显示“未连接”或进程退出判定清理成功。这里的连通性是应用内代理 DNS／HTTPS 检查，不扩大为所有桌面应用和所有网络协议已经验证。

## 诊断摘要与收尾

在两次连接结束后，真实电脑生成 2,094 字节的诊断摘要；固定格式及危险字符串检查通过。随后实际执行以下操作，始终核对为同一份冻结预览：

- 复制后应用返回本机剪贴板写入成功提示；没有读取旧剪贴板，也没有独立回读复制后的剪贴板内容。
- 在系统文件选择器中点击实际“取消”按钮，应用确认取消保存，预览不变。
- 再次打开选择器，使用独立的新文件名保存 TXT。应用完成写入、字节长度与内容及 EOF 读回核对，返回保存成功；测试脚本没有独立读取外部文档。

最终独立再次读取 12 个文件，结果稳定。节点库、节点配置、网络策略、延迟记录、恢复记录、外观及延迟请求／证明共 8 个静态文件，与导入后、连接前的基线逐字节一致（缺失文件仍缺失）；新增的连接日志和控制状态来自本次真实连接。没有用首次空安装基线掩盖这次授权导入。

应用已返回普通首页，显示“未连接”；最后一次服务仍为同会话的 `destroyed` 和 `cleanupConfirmed=true`。正常冷启动清除进程内字号参数，窗口恢复到最初的实际位置及 2090 × 1394 px 尺寸。最终检查再次确认 126 个构建输入与归档 HAP 哈希未变，并记录本轮辅助脚本哈希。本地完成记录为 `build/phase27-pc/completion.json`，原始证据保持私有。

## 本轮未覆盖

本轮没有验证电脑睡眠／唤醒、长时间后台、Wi-Fi／有线切换、完全断网恢复、真实电脑应用分流、逐项 IPv6 泄漏对照、其它 PC 型号或 API 24 真机。系统授权或企业网络限制也可能因设备环境不同而改变。原始 AX、节点导入核对材料、会话身份及运行日志仅保留在本机私有证据目录，不随 Git 发布。
