# 0.19.0：本地配置检查与失败阶段提示

本轮为 0.19.0/code40，完善节点导入、编辑及连接失败后的反馈。检查使用已有节点解析规则，不增加网络请求，不改变节点保存内容、DNS、分流、测速口径或 C++ / 原生核心。

## 配置检查

导入和编辑失败时显示字段、问题与修改建议，包括端口、UUID、认证字段、REALITY 参数和不支持的分享格式。批量导入最多展示 10 项固定格式的错误说明；部分有效内容仍需明确确认后保存。新的全失败结果会清除上一轮待保存预览，避免误保存旧内容。编辑校验失败保留草稿与原节点。

首页增加“检查配置”。连接前也会检查当前节点，并在通知授权等待后重新核对节点，防止等待期间的配置变化被忽略。检查只在本地执行；成功文案明确为“本地检查通过，尚未验证节点联网。”，不会启动临时 VPN 或代替 HTTPS 检测。

原有合法配置保持兼容，包括 TLS 可省略 SNI、REALITY 空 shortId、ALPN 的既有形式及 WebSocket Host。检查没有实现另一套完整 Xray 配置规范。IPv6 节点地址仍可导入，但当前连接入口只支持 IPv4，因此在连接前说明限制。损坏的节点库按整体读取失败处理，保留原文件，不猜测某个节点字段有误。

## 失败信息

失败分类来自执行位置和有限的已知错误码，不读取原始错误文本来猜测原因。首页与诊断页共用阶段、问题、建议组件，适配手机、平板和电脑用语。

| 阶段示例 | 能说明的范围 |
| --- | --- |
| 配置、授权、启动请求、VPN 初始化与创建 | 在对应本地或系统操作中未完成 |
| 节点地址解析、当前网络 | 物理网络上的节点入口尚未准备好；修改代理内 DoH 不一定有帮助 |
| 核心初始化、运行时时钟、转发 | 在核心或转发准备阶段失败；核心启动成功不等于节点握手成功 |
| 代理 DNS、HTTPS、响应 | 主动检查在哪一步失败；例如代理 DNS 失败也可能涉及节点或网络路径 |
| 状态、清理 | 状态读取或退出清理没有完成；不覆盖更早的启动失败 |

服务状态分别保留首次失败、清理失败与暂时性问题。开始新会话清除旧问题，恢复活动或结束时清除适用的暂时性提示；迟到结果不能写入后续会话。无效的可选诊断字段只在读取结果中被忽略，不改写原文件或清理回执。

物理网络 DNS 检查开始时也清除上一轮主动 HTTPS 检查的失败卡片，避免同一结果区同时展示新结果与旧错误；物理 DNS 的现有成功、失败和请求代次保护保持不变。

服务诊断历史延续最多 200 条的边界，仅增加固定阶段代码和原因编号，首次失败与首次清理失败各记录一次。UI 不写服务日志；原始错误、节点内容、地址与密钥不进入新增提示记录。隐私页同步说明存储范围。本轮没有增加诊断摘要导出。

## 验证状态（2026-09-14）

C4 最终候选已完成离线报告核对、两种构建核验、手机与电脑模拟器界面检查，以及正常真机连接验证。结果按下述层级分别记录，不以构建成功替代设备验证。

### 离线回归

15 套件共 898 个命名合成用例通过，另有 11 项静态页面与几何检查单列。覆盖节点解析、批量导入、编辑备份、节点库、导入导航、订阅表单、配置检查、失败分类、服务历史、连接会话与核心流程、测速会话、速率及恢复记录。C3 阶段先复用 5 套报告、补跑 11 套；C4 增加物理 DNS 成功与失败两种顺序回归，重跑受影响的连接会话和速率套件，其余 14 套复用。每套都记录当前源码、测试脚本及报告哈希。

这些计数是命名用例数量，不是互不重叠的产品保证或设备测试次数；循环中的协议、状态和宽度组合没有重复加总。最终汇总保存在本地 `build/phase23-offline/candidate4-check-result/summary.json`，与 C4 的 114 个输入绑定，C3 的汇总另行保留。另有 35 项手机测试工具的纯逻辑检查，没有执行设备命令。

### API 26 手机

从 0.18.0 覆盖升级到上述 C4 ARM64 包，使用本轮新读取的配置基线，保留用户当前节点与选择。安装前后节点库、兼容节点文件、网络策略、外观与测速历史逐字节一致；旧状态回执也保持原字节，没有恢复历史节点备份。

手动“检查配置”通过，成功提示没有宣称节点联网。检查前后 8 个配置、历史、命令与状态文件逐字节一致，记录的旧服务 PID 前后均不存在。这与纯方法测试共同验证本地检查没有发起 VPN 命令；本轮没有通过抓包直接证明零网络流量。

随后建立一条新测试会话，观察到活动状态与自动预检成功；同一会话的代理 DNS 与域名 HTTPS 检查通过。最后正常断开，收到该新会话真实的 `destroyed / cleanupConfirmed=true`，并独立确认记录的服务 PID 不存在。节点、选择、网络设置、外观与测速历史仍与本轮基线逐字节一致。

升级后的首次工具检查因旧 PID 短暂再次存在而暂停；再次确认 PID 不存在后，仅补做严格的只读升级重验，没有重复安装或放宽退出门禁。首次 HTTPS 工具读回没有滚到屏外结果区，未计为联网成功；修正工具滚动读取后，在同一会话重新检查并确认成功。这两处是测试工具的执行/读取边界，没有改变 C4 应用源码。

脱敏结果见本地 `build/phase23-phone/{local-configuration-check,upgrade-reverification,completion}.json`；原始配置、进程输出和界面树仅保存在 `.private/phase23`。本轮没有在真实手机注入坏节点或网络故障，也没有再次执行强制退出实验。

### 模拟器中的错误输入

C4 手机模拟器已实际完成同一表单中的部分成功预览到全部失败的替换流程。先确认部分成功按钮存在但不点击；替换为全失败后，结果区分别显示 UUID 与端口问题，完整界面树（包括不可见项）均没有旧部分导入按钮，滚动到底部仍无旧确认入口。节点库字节保持不变。

C4 电脑模拟器中，把示例节点端口从 443 改为 70000 后点击保存，页面显示端口字段、问题与建议；无效草稿仍为 70000，独立回读确认实际节点端口仍为 443，节点库字节未改变。

C4 手机还检查两倍字号下错误卡片的滚动阅读、首页对 IPv6 节点入口限制的本地提示，以及独立的“本地节点库”读取失败提示。后两项均保留原合成文件字节，没有通过替换或修复文件来伪造检查成功。

### 范围与限制

异常路径采用实际方法的合成故障注入与独立模拟器中的界面观察；真实手机仅验证当前有效节点、本地配置检查和正常连接流程，不为制造错误修改用户节点。x86_64 预览不含转发核心，不计为 VPN 联网通过。本轮没有运行平板模拟器，也不新增真实平板或电脑的联网验收。

模拟器沿用独立测试实例及其真实基镜像依赖，不清空旧数据盘、不改写旧平板的版本字段。测试配置使用合成节点，结束后已恢复本轮新鲜基线并独立回读；手机节点没有从旧备份恢复。
