# 0.12.0：手机、平板与电脑窗口自适应

当前版本为 **0.12.0/code32**。本阶段改进多端界面、窗口尺寸响应与构建能力隔离，保留 0.11.1 的节点编辑、备份、分流和批量检测业务。manifest 声明 `phone`、`tablet`、`2in1`，支持全屏、分屏和浮窗；折叠屏通过窗口宽度使用相同布局规则。

**x86_64 模拟器包仅用于界面预览，不包含 VPN 核心，不能作为联网通过的证据。真实平板网络验证按用户要求留到最后，当前尚未完成；PC 联网也未通过验收。**

## 用户可见变化

- 表单、说明页和诊断页最多 840 vp 并居中，标题、滚动内容和固定保存区对齐；窄窗口使用可用宽度。
- 连接、节点和设置在窗口宽度达到 1024 vp 时使用左侧 176 vp 导航；窄于该阈值时保留底部导航。
- 首页在**可用主内容宽度达到 680 vp**时使用双栏。计算时先扣除侧栏；阈值不是截图的物理像素宽度。主内容和节点列表分别有独立上限。
- 窗口大小改变后重新计算布局。设置页外观选项使用最小高度，支持系统字号；保留现有手机操作和控件 ID。
- PC 缺少系统扫码能力时，扫码按钮不可用且不加载对应 ScanKit 模块。用户仍可粘贴分享链接或单 outbound JSON，也可从设置恢复节点备份。手机支持的 QR-only 系统扫码、单结果和相册入口保留。本阶段没有 PC 图片识码实现。

布局规则位于 `model/AdaptiveLayout.ets`，窗口监听位于 `entryability/EntryAbility.ets`。`Scan.Core` 是公共扫码类型能力，不足以证明具备系统扫码或图片解码；实际入口检查 `SystemCapability.Multimedia.Scan.ScanBarcode` 后才动态加载 `model/NodeScanner.ets`。

## 已完成的界面观察

所有以下记录都来自不含 VPN 核心的 x86_64 预览包，没有向模拟器导入真实节点凭据。节点由调试沙箱写入合成 `node-catalog` fixture；不能把节点显示成功记为完成实际键盘、剪贴板或扫码导入。

| 场景 | 已记录内容 | 证据边界 |
| --- | --- | --- |
| 手机模拟器 | 首页、节点列表、网络设置、编辑页、设置页和 2 倍字号 | 正常纵向窗口；旋转未通过，不能声称横屏完成。 |
| 平板模拟器 | 首页双栏、主入口侧栏、节点列表、网络设置、编辑页、设置及 2 倍字号 | 这是模拟器布局，不是真实平板联网。 |
| PC 模拟器 | 默认/中等/窄/最小/宽/恢复窗口；侧栏与底栏切换、首页单/双栏；深色/跟随系统、窄窗口 2 倍字号、Tab/Enter 导航、节点/编辑/导入/网络设置 | 只验 UI。显示网络设置页不等于执行了 DNS 或代理请求。 |
| 折叠屏模拟器内屏 | 707.2 vp 内屏下，最终首页双栏和底部导航已目检；2 倍字号下统计标签自然换行；备份页目检正常；另有订阅、关于、隐私与诊断页记录 | 这些是内屏静态页面观察，不是内外屏连续切换或完整旋转验收。 |

`fold-home-default` 是 680 vp 阈值修复前的对照，记录双栏为 false；`fold-home-final` 是修复后记录，双栏为 true。仅凭相同的 px `appBounds` 不能推断应用使用的 vp 或包版本，必须结合安装记录、实际窗口密度和包哈希。

本地 JSON 中的 `horizontalOverflow=[]` 表示检查器未发现**被记录的可见控件**超出应用左右边界。它不证明每个字形、隐藏控件、纵向滚动或所有大字号都无裁切。侧栏/双栏布尔值只说明该次快照是否存在对应控件，不是对全部页面的合格判定。

手机模拟器首次调用输入法遇到小艺隐私弹窗后选择取消，实际 IME 输入流程未完成。PC 本轮只确认 Tab/Enter 导航，系统扫码能力降级页面已打开；没有把“导入页可显示”记为剪贴板或文件导入成功。备份恢复等文件选择器端到端功能沿用 [0.11.1 真机记录](phase11-network-node-tools.md)，本轮只核对相关页面。

## 已完成的离线与构建检查

当前相关离线检查合计 **447 项通过**，其中窗口/布局函数与监听生命周期检查为 **21 项**，次级页面 ArkTS 组件树与宽度绑定检查为 **11 页**。旧的 18 项布局结果已由 21 项版本替代，不能把二者叠加。次级页面检查在多个逻辑窗口宽度下执行真实宽度绑定，并验证固定区域和滚动内容对齐。

最终独立复查重跑的 6 套、231 项检查均通过，未发现新增问题；这些检查包含在上述 447 项内，不能再次相加。

扫码能力与动态模块加载的合成回归包括：不支持时不加载 ScanKit、不调用扫码 API、仍能粘贴导入；页面退出或连接状态变化后不启动迟到扫码。预览版设置入口也验证了开发工具被禁用，而外观、网络表单和备份入口仍可用。

完整 ArkTS/打包/签名构建已通过，x86_64 预览包还检查了 ABI 与未打包真实核心。离线测试使用合成 SDK、文件或状态；构建和截图都不能替代 VPN 数据通路测试。原生源码版本与历史构建范围见 [Hev README](../native/hev/README.md)、[Xray/Go README](../native/xray26/README.md) 和[首次公开冷构建记录](publication-validation.json)，这些历史记录不是 0.12.0 新的跨架构联网验收。

## 尚未通过或仍待验证

- **手机旋转**：尝试旋转时宿主 `Emulator.exe` 退出，错误 `00802003`，没有成功的应用横屏帧。保留为未通过，不能据此直接判定应用旋转逻辑有缺陷或已修复。
- **折叠屏内屏到外屏**：执行 `foldedState close` 时宿主模拟器退出，同为 `00802003`，没有成功的外屏应用帧。内屏双栏成功不补足这一缺口。
- **真实平板网络**：按约定最后进行；仍需确认实际型号、系统、签名条件，再用 ARM64 完整核心包核对授权、DNS/HTTPS、停止与资源清理。当前 `tabletNetworkVerified=false`。
- **真实鸿蒙 PC 与 x86_64 预览限制**：真实鸿蒙电脑尚未联网验收，当前 `pcNetworkVerified=false`。ARM64 电脑可走现有完整核心包的构建路径，但仍需验证实际系统 API、签名和数据通路。Go OpenHarmony amd64 的 TLS/运行时适配问题属于当前 x86_64 模拟器核心的限制，不能外推为所有真实鸿蒙电脑都必须先移植 amd64。
- **实际输入与导入**：系统输入法、剪贴板、扫码及 0.12.0 文件选择器全流程仍未完成本轮验收，不能用沙箱写入 fixture 或静态页面截图替代。
- 真实订阅服务、真实域名节点、全天稳定性、续航、多设备协议覆盖以及全面无障碍检查，仍按既有阶段边界分别验收。

## 本地证据与复查

安全投影 JSON 与同名 JPEG 位于忽略的 `build/phase12-emulators/`。启动、锁屏、调试素材和原始 AX 树不纳入画廊；`pc-settings-system` 是有效的“跟随系统主题”记录，不是系统启动素材。

```powershell
node scripts/make-adaptive-report.cjs
```

打开同目录 `report.html` 可按手机/平板/PC/折叠屏筛选、查看 bounds、侧栏/双栏、横向溢出记录并打开原图。脚本不修改截图像素，仅重写本地报告，新增截图后可重跑。画廊数量以生成时有效记录为准，最终包归属以 `final-verification.json` 为准。

贡献者应保留控件 ID、窗口监听清理和 BuildCapabilities 门控；不要为了让预览“看起来能连”而伪造连接状态。构建和设备验证步骤见[多端贡献者检查](public-build.md#5-多端界面贡献者检查)。

本轮模拟器 UI 收尾时已关闭全部模拟器，进程核对未发现 `Emulator`，HDC 目标列表为空。该状态是收尾时的检查，不应作为后来设备连接状态的证明。
